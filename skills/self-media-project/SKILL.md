# 自媒体内容项目

把创作者的账号背景、选题和材料整理成可持续使用的项目上下文。项目应让后续任务知道先读什么、材料在哪里、结果保存到哪里。

## 开始前

1. 检查目标目录和已有文件，先列出现状。
2. 如果目录非空，保留原文件；创建新版本或先请求覆盖授权。
3. 读取用户提供的账号介绍、历史内容、读者反馈和素材清单。
4. 缺少账号方向、目标读者或事实边界时，提出最少的阻塞问题，不代替用户决定。

如果用户希望从模板开始，可参考仓库中的 `starter-project/`。

## 项目结构

最小结构为：

```text
账号说明书.md
选题库.md
项目使用说明.md
素材库/
公众号文章/
小红书图文/
视频脚本/
视觉素材/
发布记录/
复盘记录/
```

用户暂时不用的平台目录可以保留为空，但不要创建直播、投流、私域等本书范围外的系统。

## 工作流程

1. 盘点现有资料，区分账号事实、作者判断、候选想法和待核查信息。
2. 起草或更新 `项目使用说明.md`，写清各目录用途、开始任务前应读取的文件和保存规则。
3. 起草 `账号说明书.md`：账号定位、目标读者、核心主题、表达风格、事实边界、禁区和人工确认项。
4. 整理 `选题库.md`：母题、读者问题、中心判断、可用素材、适合平台、状态和下一步。
5. 为素材库和视觉素材建立索引。引用原文件路径，不移动或改写原始材料，除非用户明确要求。
6. 检查所有路径真实存在，模板字段能被后续 Skill 读取。
7. 向用户列出新增、保留和待补充内容。

## 人工确认

以下内容必须由用户确认：

- 账号长期方向和目标读者。
- 哪些观点代表作者。
- 哪些经历、案例和数据可以公开使用。
- 是否修改任何已有文件。

## 完成标准

- 后续平台 Skill 能找到账号说明书、选题和素材。
- 没有把候选想法写成确定事实。
- 没有覆盖原始材料。
- 项目结构清楚，但没有为了显得完整而创建无用文件。
- 不自动发布，不操作外部平台，不创建 Automation。
