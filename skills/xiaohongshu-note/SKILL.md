# 小红书图文工作流

小红书不是公众号文章的缩写。围绕具体场景、信息分层、收藏价值和封面表达重新设计内容。

## 必要输入

- `账号说明书.md`
- 已确认母题、选题记录或公众号文章
- 素材库中的真实经历、读者问题、案例或事实
- 视觉素材中的参考和禁用方向；如没有，应明确说明

没有可公开的真实素材时停止并请求补充。不得制造“亲测”“我靠这个成功”等个人体验。

## 按阶段执行

1. **平台判断**：判断母题是否足够具体，能否形成场景、清单、教程、对比或避坑。
2. **角度**：给出三个小红书角度，分别说明目标读者、开头场景、正文结构和收藏价值。
3. **选题卡**：用户确认后保存角度、标题方向、素材、结构和风险。
4. **正文**：使用短段落和清楚的信息层级；重新组织，不压缩公众号全文。
5. **图文页**：把信息拆为可以独立阅读的页，不机械切句。
6. **封面**：先给封面方向、主副标题、构图和留白，再在用户确认后生成图片 Prompt。
7. **发布准备**：生成事实核查、视觉检查和人工发布清单。

## 人工确认

- 三个角度后确认主角度。
- 个人经历、案例和表达口吻由作者确认。
- 封面主标题与视觉方向确认后再写图片 Prompt。
- 发布文案和最终图片必须由用户检查。

## 输出

```text
小红书图文/<选题名称>_小红书选题卡.md
小红书图文/<选题名称>_正文初稿.md
小红书图文/<选题名称>_图文页文案.md
小红书图文/<选题名称>_封面方案.md
小红书图文/<选题名称>_图片生成提示词.md
小红书图文/<选题名称>_发布清单.md
```

保留来源文章和每个已确认版本，不覆盖原文件。

## 检查

- 开头是否有具体问题或场景，而不是泛泛介绍。
- 正文是否适合小红书，而不是公众号式长段落。
- 是否有真实、可使用的素材和明确行动。
- 标题是否夸张，封面文字是否过多，正文与封面是否一致。
- 图片 Prompt 是否要求清楚构图和留白，并避免仿冒真实产品界面。
- 不自动发布，不操作小红书账号，不把经验数字写成平台硬规则。
