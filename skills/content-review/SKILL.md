# 内容复盘与项目检查

让发布结果和执行过程进入下一轮内容判断。复盘关注发生了什么、为什么、哪些经验可复用和下一步做什么。

## 选择模式

- **发布复盘**：针对一条已发布内容。
- **周期复盘**：针对一周、两周或一个月的内容。
- **Goal 检查**：对照目标、完成标准和现有产出检查进度。
- **项目健康检查**：检查文件缺失、长期未更新的选题、未复盘内容和流程阻塞。

只读取当前模式需要的记录。没有数据时报告“无法判断”，不要编造表现或原因。

## 工作流程

1. 确认检查周期、目标和可用文件。
2. 区分已观察事实、作者反馈和推断。
3. 汇总完成项、未完成项、阻塞和资料缺口。
4. 对内容表现只提出有证据的解释；把其他解释标为假设。
5. 提炼可复用经验和需要停止的做法。
6. 给出数量有限、能够执行的下一步，并标明需要作者决定的事项。
7. 另存复盘或检查记录，不改写发布内容。

## 输出

```text
复盘记录/<周期>_内容复盘.md
复盘记录/内容复盘总表.md
自动化/健康检查记录/<日期>_健康检查.md
自动化/Automation运行记录.md
```

只在相应目录存在或用户要求创建时写入。Automation 模板可参考仓库 `automation-templates/`。

## 人工确认

- 账号方向、内容取舍和下一周期目标由用户决定。
- 不能根据少量数据断言平台规律或因果关系。
- 涉及删除、归档、大量移动或覆盖文件时必须单独获得授权。
- 创建或修改 Automation、Thread Automation 需要用户明确要求；本 Skill 不自动创建。

## 检查

- 每项结论能否追溯到发布记录、内容文件或用户反馈。
- 是否把“没有数据”误写成“表现不好”。
- 是否区分计划未完成、资料不足和流程主动停止。
- 是否把建议写成用户已经决定的行动。
- 不自动发布，不自动删除，不自动创建定时任务。
